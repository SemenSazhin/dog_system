# Что сделано в блокноте: разбор по ячейкам вывода

Источник: `new/PoopDetector.ipynb`, блок «Эксперименты: ключевые точки». Презентация: `keypoint_experiments.pptx`
(пересобирается командой `python scripts/build_presentation.py`, цифры берутся из вывода ноутбука).

## Вопрос эксперимента
Помогает ли подавать в LSTM не все 20 ключевых точек позы собаки, а только их группу
(позвоночник, таз, хвост, лапы), и нужны ли точки вообще по сравнению с одной рамкой (bbox) собаки.

## Ячейки по порядку

**Конфиги экспериментов** (`KEYPOINT_EXPERIMENTS`). Задаёт 7 конфигураций: без точек, все 20, позвоночник+таз (0-9),
таз+хвост (6-12), только хвост (10-12), только лапы (13-19), позвоночник+хвост (0-5, 10-12).
Параметры: 12 эпох, batch 32, lr 1e-3.

**Функции экспериментов.** Вывод: «✅ Функции экспериментов готовы». Внутри: извлечение признаков из видео,
случайный сплит окон 64/16/20, обучение LSTM, выбор лучших весов по F1 на валидации, подсчёт метрик на тесте,
графики (история обучения, confusion matrix, ROC) для каждого эксперимента.

**Запуск серии «комбинации точек»** (основной вывод). Для каждой конфигурации:
1. `Extracting features` - проход по 106 видео «норма» и 60 видео «дефекация», нарезка окон по 120 кадров;
   в логе «Извлечено N последовательностей из <видео>».
2. Итог по данным: с позой 348 окон (194 норма / 154 дефекация), без позы 411 (251 / 160): без позы нет
   отсева кадров, где поза не найдена.
3. 12 строк обучения `loss / val_loss / val_acc / val_f1`: loss падает (например 2.8 → 0.5), val-метрики
   шумят от эпохи к эпохе - признак малой валидационной выборки.
4. Строка `✅ [name] acc=… f1=… roc_auc=…` - тестовые метрики.
5. Графики: история обучения, confusion matrix, ROC.

Посчитаны 6 конфигураций из 7. На «позвоночник + хвост» расчёт прерван вручную
(`KeyboardInterrupt`), поэтому в сводке её нет.

**Сводка экспериментов.** Таблица и столбчатый график F1, лучший эксперимент:

**Мультисид-прогон** (добавленные ячейки). Запущен, но прерван на извлечении признаков первой конфигурации,
результатов нет.

## Выводы
- **Точки позы помогают.** Все 20 точек дают F1 0.86 против 0.72 у одной рамки; ROC-AUC 0.96 против 0.87.
- **Группировка точек в этом прогоне не помогла.** Ни одно подмножество не превзошло все 20 точек;
  лучшие - «только хвост» (0.772) и «позвоночник + таз» (0.767), на 0.09 ниже.
- **Лапы в одиночку вредны:** F1 0.65 и ROC-AUC 0.70, хуже bbox.

## Почему это пока не окончательно
- Тест около 70 окон: одно окно меняет F1 на 0.02-0.03, а разница между группами 0.01-0.09.
  Различия «хвост» / «позвоночник + таз» / bbox лежат в пределах шума; надёжным выглядит только отрыв «все точки» от остальных и провал «только лапы».
- Один запуск, один сид.
- Окна делятся случайно, а не по видео, поэтому соседние окна одного ролика есть и в train, и в test: метрики завышены.
- Тест для «без точек» состоит из других окон (411 против 348).
- «Позвоночник + хвост» не посчитана.
